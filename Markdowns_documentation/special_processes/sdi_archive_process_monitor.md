## Purpose

Track the discussion, decisions, risks, and code/documentation changes for the SDI packaging, Planon export, archive, retrieve, and package-delete flow.

## Tables In Scope

- `sdi_dataset`: approved Mechanical and Backflow source rows.
- `sdi_dataset_EL`: approved Electrical source rows.
- `sdi_print_out`: active SDI package rows shown in Packaged Assets.
- `sdi_print_out_arch`: archived SDI package rows.

## Current Verified Behavior

Verified from `SDI_process/app.py` and read-only DB checks on 2026-06-02.

- Approved source rows enter SDI eligibility from `sdi_dataset` and `sdi_dataset_EL` only when `Approved == "1"`.
- Unpackaged Assets is a view built from approved source rows after excluding QRs already in `sdi_print_out`, `sdi_print_out_arch`, or `QR_codes.sdi = 1`.
- Pressing **Create SDI Package** creates a new `id_print_out` and writes rows directly into `sdi_print_out`.
- Packaged Assets is a view over `sdi_print_out`.
- **Export to Planon** generates the export/validation output and sets `sdi_print_out.print_out = 1` for exported rows.
- **Archive** copies package rows from `sdi_print_out` to `sdi_print_out_arch`, then deletes them from `sdi_print_out`; it is hard-blocked unless every selected row has `print_out = 1`.
- **Retrieve** copies selected package rows from `sdi_print_out_arch` back to `sdi_print_out`, then deletes them from `sdi_print_out_arch`; it preserves source and review JSON approval.
- **Exclude** deletes an active package from `sdi_print_out`; it preserves approval first, so non-manual rows can reappear in Unpackaged Assets.
- ME/BF/EL automated review JSON sync now treats any QR in `sdi_print_out` or `sdi_print_out_arch` as package-locked and coerces source approval to approved (`Approved = "1"` in `sdi_dataset` / `sdi_dataset_EL`, JSON `structured_data.Approved = "True"`).
- Package actions write audit rows for package ID, row count, QR list, source table, target table, and action.

## State Model

```text
Approved review save
  -> sdi_dataset / sdi_dataset_EL
  -> Unpackaged Assets view
  -> Create SDI Package button
  -> sdi_print_out with id_print_out
  -> Packaged Assets view
  -> Export to Planon sets print_out = 1
  -> Archive button
  -> sdi_print_out_arch
  -> Retrieve button
  -> sdi_print_out
```

Important distinction: there is no separate intermediate "Packaged Assets" table. The Packaged Assets tab reads `sdi_print_out`.

## Decisions

- Archive is allowed only after all rows in the package have `print_out = 1`.
- Retrieve preserves source and review JSON approval.
- Exclude preserves approval before deleting active package rows, so approved non-manual rows return to Unpackaged Assets.
- Existing route URLs remain unchanged; user-facing wording distinguishes **Create SDI Package** from **Export to Planon**.
- Package actions write audit-trail entries with user, package ID, row count, QR list, source table, and target table.
- Active/archive uniqueness is enforced through route preflight checks and SQLite guardrail indexes/triggers installed by `scripts/migrate_sdi_package_db_guardrails.py`.
- Full foreign-key package-table rebuild is deferred; this guardrail phase uses expression indexes and triggers only.

## Risks To Monitor

- Historical archive rows may still have `print_out != 1`; the Archive hard block and archive-insert trigger prevent new unexported archive moves, and `scripts/audit_sdi_package_integrity.py` reports existing rows as warnings.
- Database guardrails now block duplicate package QRs, active/archive overlap, blank package keys, package rows without a `QR_codes` parent, unapproved packaged source state, unexported archive inserts, packaged-row unapproval, and `QR_codes` deletes while packaged.
- Package IDs are generated by `sdi_sequence` plus the max IDs in active/archive tables. This is reasonable, but concurrent packaging should still be considered a risk under SQLite write contention.
- Exclude deletes package rows from `sdi_print_out` and validation outputs after audit logging; it is not an archive operation.
- Route names still include legacy `/export`, but user-facing text now says **Create SDI Package**; **Export to Planon** remains the Planon file/export action.

## Suggested Safeguards

- Maintain the implemented route preflight checks for Package, Archive, Retrieve, and Exclude.
- Keep `scripts/migrate_sdi_package_db_guardrails.py` idempotent and run it after package-table schema changes.
- Keep package action audit logging for Package, Planon Export, Archive, Retrieve, and Exclude.
- Run the read-only health check for:
  - QRs in both `sdi_print_out` and `sdi_print_out_arch`
  - duplicate QRs within either table
  - missing or blank `id_print_out` or `"QR Code"`
  - missing guardrail indexes/triggers
  - package IDs present in both active and archive
  - packaged/archive QRs missing from source datasets
  - packaged/archive QRs whose source or review JSON approval is not approved
  - archived rows whose `print_out` is not `1`
- Consider a package status field or event table instead of relying only on row location and `print_out`.
